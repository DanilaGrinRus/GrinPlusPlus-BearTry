работы по продукту. Статусы те же, что в [STATUS.ru.md](STATUS.ru.md). Дат не
обещаем; критерий выхода каждого пункта — доказательство.

## Фаза 1 — живая проверка кандидата

Цель: завершённый живой прогон Floonet, привязанный к бинарнику кандидата.

| Пункт | Статус | Критерий выхода |
|---|---|---|
| Живая синхронизация Floonet кандидата | **В ПРОЦЕССЕ** | Свежий изолированный профиль: заголовки → PIBD → проверка → догон → `fully_synced`; доказательство привязано к `4039086C…` |
| Перезапуск после полной синхронизации | **PARTIAL** | Tip/состояние сохраняются, продолжение без повторной загрузки state |
| Перезапуск во время загрузки PIBD | **NOT VERIFIED** | Стадия задокументирована; состояние сохранено или безопасно перезапущено |
| Перезапуск во время проверки/активации | **NOT VERIFIED** | Marker-recovery проверен; нет частичного live-состояния |
| Перезапуск во время построения индекса / первого догона | **NOT VERIFIED** | Продолжение или безопасный rebuild; нет потери данных |

## Отдельные треки (не Node Beta)

- **Кошелёк:** live-приёмка отправки/получения/восстановления, работа с ключами,
  миграция и security review. Сейчас **NOT READY**.
- **UI:** согласование с фактическим backend-контрактом, безопасность
  процессов/профилей и сквозная приёмка в отдельном репозитории. Сейчас
  **NOT READY**.
- **Flint/messenger/own-network research:** только дизайн; не часть релиза этого
  репозитория.

## Правило остановки

Не искать бесконечно редкие дефекты. Когда проверок для конкретного режима
достаточно, зафиксировать PASS/FAIL/NOT VERIFIED, остаточный риск и кандидата.
Никогда не смешивать данные кошелька, порты, live-копии и каталоги сборки между
параллельными прогонами. Хеш или mock не заменяет live-проверку, и ни один
секрет, seed или приватный ключ не должен попадать в отчёты или логи.
